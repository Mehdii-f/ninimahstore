# سیسمونی نی‌نی ماه

فروشگاه‌ساز استاتیک فارسی (RTL) برای فروشگاه سیسمونی و لوازم نوزاد؛ بدون وابستگی و بدون نیاز به Build. مناسب انتشار روی **GitHub Pages**.

## ساختار پروژه

```
index.html          صفحه اصلی
css/style.css       استایل (پالت آبی زنده)
js/config.js        تنظیمات قابل ویرایش (نشست مدیر، آدرس پنل، ...)
js/app.js           منطق سایت و پنل مدیریت
assets/logo.png     لوگوی فروشگاه (بچه و ماه، با پس‌زمینهٔ شفاف)
assets/favicon.png   آیکون تب مرورگر (ساخته‌شده از لوگو)
assets/logo-placeholder.svg   (نمایش موقت تا وقتی logo.png را نگذاشته‌اید)
```

## اجرا و انتشار

1. لوگو از قبل در `assets/logo.png` قرار دارد (برای تغییر: از پنل مدیریت یا همان فایل را جایگزین کنید).
2. روی کامپیوتر: پوشه را با یک وب‌سرور ساده باز کنید (مثلاً `python -m http.server`) و به `http://localhost:8000` بروید.
3. روی گیت‌هاب: ریپازیتوری بسازید، فایل‌ها را Push کنید، سپس `Settings → Pages → Deploy from a branch → main / (root)`.

> رمزنگاری مرورگر (Web Crypto) فقط روی **https** یا **localhost** کار می‌کند. GitHub Pages خودش https است.

## ورود به پنل مدیریت

سایت **ورود مشتری ندارد** و دکمهٔ مدیریت هم در صفحه نیست. پنل با این آدرس باز می‌شود:

```
https://آدرس-سایت-شما/#admin
```

(کلمهٔ `admin` را می‌توانید در `js/config.js` با `ADMIN_ROUTE` عوض کنید.)

### راه‌اندازی اولیه (فقط یک بار)
1. نام کاربری غیرمعمول (نه admin و نه نام فروشگاه) و رمز قوی بسازید. دکمهٔ «ساخت رمز قوی تصادفی» یک رمز تصادفی می‌سازد؛ آن را در یک مدیر رمز عبور ذخیره کنید.
2. کلید نمایش‌داده‌شده را در برنامهٔ **Google Authenticator / Authy / Microsoft Authenticator** وارد کنید (Enter a setup key) و کد ۶ رقمی را بزنید.
3. **۸ کد بازیابی** را در جای امن ذخیره کنید. هر کد فقط یک بار کار می‌کند و اگر گوشی را گم کردید، جای کد برنامه استفاده می‌شود.

### ورود
نام کاربری + رمز عبور + کد ۶ رقمی برنامه (یا یک کد بازیابی).

## تغییر عکس‌ها (بدون دست‌زدن به کد)

### از داخل سایت (پیشنهادی)
وارد پنل شوید، سپس تب‌ها:
- **محصولات**: افزودن، ویرایش، حذف و تغییر عکس هر محصول (آپلود فایل یا لینک https)
- **دسته‌بندی‌ها**: افزودن/حذف و تغییر نام و آیکون
- **اسلایدر**: افزودن، حذف و جابه‌جایی عکس‌های بخش «درباره ما»
- **تنظیمات و لوگو**: تغییر لوگو، متن‌ها، تلفن، واتساپ، اینستاگرام، تلگرام و آدرس

آپلودها قبل از ذخیره کوچک و فشرده می‌شوند (و اطلاعات EXIF حذف می‌شود).

### از طریق فایل (برای عکس‌های ثابت پروژه)
فایل عکس را داخل `assets/` بگذارید، سپس در پنل مدیریت به‌جای لینک، مسیر نسبی را بنویسید؛ مثلاً `assets/slides/1.jpg`.

## امنیت ورود مدیر

| مورد | وضعیت |
|---|---|
| ورود دومرحله‌ای | نام کاربری + رمز + کد TOTP (استاندارد RFC 6238) یا کد بازیابی |
| ذخیرهٔ رمز | PBKDF2-SHA256 با Salt تصادفی و ۶۰۰٬۰۰۰ تکرار؛ **هیچ رمز پیش‌فرضی در کد وجود ندارد** |
| نام کاربری | فقط به‌صورت هش ذخیره می‌شود؛ از روی localStorage قابل خواندن نیست |
| راز TOTP | با AES-GCM و کلیدی که از رمز عبور مشتق می‌شود رمز شده است؛ بدون رمز عبور قابل خواندن نیست |
| کد تکراری | هر کد TOTP فقط یک بار پذیرفته می‌شود (ضد Replay) |
| ضد Brute-Force | قفل پس از هر ۳ تلاش ناموفق (۶۰ ثانیه، بعد دو برابر، تا یک ساعت) + تأخیر تصادفی؛ پیام خطا مشخص نمی‌کند کدام بخش اشتباه بوده |
| گزارش تلاش‌ها | در ورود موفق بعدی، تعداد تلاش‌های ناموفق قبلی نمایش داده می‌شود |
| نشست | فقط در `sessionStorage`؛ پایان خودکار بعد از ۱۰ دقیقه بی‌فعالیتی، سقف مطلق ۲ ساعت، و قفل شدن اگر تب بیش از ۵ دقیقه پنهان بماند |
| تغییر رمز | نیازمند رمز فعلی و یک کد TOTP تازه |
| XSS | هیچ `innerHTML` با داده کاربر وجود ندارد؛ همه چیز با `textContent`؛ آدرس تصاویر فقط `https`/مسیر نسبی/`data:image` |
| CSP | سیاست `Content-Security-Policy` در `index.html`؛ بدون اسکریپت inline |
| Clickjacking | اگر سایت داخل iframe باز شود، محتوا نمایش داده نمی‌شود |

### محدودیت مهم (صادقانه)
این پروژه **بدون سرور** است. حساب مدیر و تغییرات پنل در **localStorage همان مرورگر** می‌مانند، و این یعنی:

- پنل مدیریت **تنها محتوای یک پیش‌نویس محلی** را عوض می‌کند. سایتی که بازدیدکنندگان می‌بینند فقط با Commit کردن در گیت‌هاب عوض می‌شود (بخش بعد). پس **قفل واقعی سایت زنده، حساب گیت‌هاب شماست**؛ حتماً **تایید دومرحله‌ای (2FA)** گیت‌هاب را فعال کنید و رمز قوی بگذارید.
- کسی که مرورگر شما را در اختیار دارد (یا حافظهٔ سایت را پاک می‌کند) می‌تواند پنل آن مرورگر را از نو راه‌اندازی کند؛ ولی هیچ تاثیری روی سایت منتشرشده ندارد.
- ریپازیتوری عمومی است؛ پس آدرس پنل (`ADMIN_ROUTE`) مخفی نیست و فقط مزاحمت را کم می‌کند.

## انتشار رایگان تغییرات برای همه بازدیدکنندگان

سایت هنگام باز شدن، فایل `data/site.json` را می‌خواند و همان را به همه نشان می‌دهد. روند کار:

1. در پنل مدیریت تغییرات را بدهید (محصول، عکس، دسته‌بندی، اسلایدر، تنظیمات).
2. `پنل ← امنیت و پشتیبان ← دانلود بستهٔ انتشار (ZIP)`
3. فایل ZIP را باز کنید؛ پوشه‌های `data` و `assets` ساخته می‌شود (عکس‌های آپلودشده به‌صورت فایل جدا داخل `assets/uploads` هستند تا سایت سنگین نشود).
4. در گیت‌هاب: `Add file ← Upload files`، دو پوشه را بکشید و `Commit` کنید.
5. چند دقیقه بعد همه تغییرات را می‌بینند.
6. در پنل، «حذف پیش‌نویس» را بزنید تا مرورگر خودتان هم نسخهٔ منتشرشده را نشان دهد.

نکته: تا زمانی که پیش‌نویس دارید، مرورگر شما نسخهٔ پیش‌نویس را نشان می‌دهد، نه نسخهٔ منتشرشده.

## دکمهٔ «استعلام / سفارش»

اگر در تنظیمات شماره واتساپ ثبت کنید، پیام آمادهٔ حاوی نام محصول در واتساپ باز می‌شود؛ در غیر این صورت اگر تلفن ثبت شده باشد، تماس تلفنی شروع می‌شود.

## گم شدن گوشی یا رمز

- گوشی گم شد: با یکی از **کدهای بازیابی** وارد شوید (هر کد فقط یک بار).
- رمز یا همهٔ کدهای بازیابی گم شد: قابل بازیابی نیست (چیزی از رمز ذخیره نمی‌شود). داده‌های سایت (localStorage) همان مرورگر را پاک کنید و حساب را دوباره بسازید. سایت منتشرشده در گیت‌هاب دست‌نخورده می‌ماند؛ فقط پیش‌نویس محلی از بین می‌رود، پس پیش از آن «دانلود پشتیبان» بگیرید.

## هدرهای امنیتی بیشتر

GitHub Pages اجازهٔ تنظیم هدر نمی‌دهد. اگر روی Cloudflare/Netlify/Nginx میزبانی کردید، این هدرها را هم اضافه کنید:
`Content-Security-Policy` (با `frame-ancestors 'none'`)، `X-Content-Type-Options: nosniff`، `Strict-Transport-Security`.
